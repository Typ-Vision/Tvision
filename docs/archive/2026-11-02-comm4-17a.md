# COMM4-17a — TCP UI kabulünde doğru editör bağlamını geri yükleme

Uygulayıcı: Codex

2 Kasım 2026. Kullanıcı bu düzeltmede kısa/hedefli doğrulama istedi;
tam kapanış regresyonu COMM4-26'ya bırakıldı.

## Neden ve değişiklik

`ui_publication_editor` geçerken `ui_tcp_acceptance` ve
`ui_multi_endpoint_acceptance`, `slot editor controls exist` ile duruyordu.
Ortak `verifyPublicationUi` TCP dalında loaded snapshot izolasyonunu sınamak
için `Selected draft only` adında başka reçete seçiyor ve Runtime sayfasına
geçiyordu. Ardından COMM4-17 slot senaryosu yayın aracının reçetesine dönmeden
`showToolProperties` çağırıyordu. Seçili reçetede publisher bulunmadığından
slot kontrolleri oluşmuyordu; bu bulgu üretim slot editöründe eksiklik değildir.

`tests/editor_publication_ui.cpp`, slot senaryosundan önce özgün reçeteyi,
Editor sayfasını ve publisher aracını açıkça yeniden seçiyor; fixture bağlamını
doğruluyor. Ürün kodu değişmedi; önceki TCP/ACK, loaded-recipe izolasyonu,
restart izinleri ve slot/atomik Apply kontrolleri korunuyor.

## Yeni doğrulama

- Başlangıç: aynı üç testte publication geçti, iki TCP testi yukarıdaki hatayla kaldı.
- Incremental Release ON `visionflow` derlemesi geçti.
- Son kaynakta `ctest --test-dir build/reference-ui -R
  '^ui_(publication_editor|tcp_acceptance|multi_endpoint_acceptance)$'
  üç testin tamamını geçti (8.37 saniye).
- `build/comm4/COMM4-17a/build.log` ve `ctest.log` yeni koşum kanıtlarıdır.
  Mevcut UI kabulü geçici fixture üretir; kullanıcı `config/local.ui.ini`
  değiştirilmedi. Testlerin normal/küçük görüntü üretimi de geçti; bu görevde
  native/DPI veya kapsamlı görsel kabul iddiası yoktur.
- Graph `list_projects`, `index_status`, `check_index_coverage` çağrıları
  `Transport closed` döndürdü; bu boş arama sonucu sayılmadı. İlgili test,
  MainWindow property seçimi ve PublishDataEditor kaynakları doğrudan okundu.
