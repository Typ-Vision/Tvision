# ICM-04a — backend session ve handle ömrü tamamlandı

17 Ekim 2026. Uygulayıcı: Claude Code. Gerçek cihaz bulunmadı; open/feature/grab denenmedi.
[Görev kartı](../architecture/industrial-camera-tasks-foundation.md),
[backend kararı](../architecture/industrial-camera-backend-decision.md),
[uygulanan ömür özeti](../architecture/industrial-camera-contract-plan.md) (§5 sonu).

## Kapsam ve dosyalar

- `src/hardware/OecsCApi.{hpp,cpp}`: SDK başlığı içermeyen `OecsCApi` vendor sınırı
  (load/unload, SDK sürümü, USB enumerate, create/open exclusive/close/destroy), `OecsDeviceInfo`
  ve yorumlanan MV_* kodları. `VISIONFLOW_WITH_OECS_SDK` varsa `OecsDynamicApi`: QLibrary ile
  `MvCameraControl.dll`, `decltype(&::MV_CC_*)` pointer'ları, eksik export'ta unload; canlı handle
  varken `unload()` reddedilir. Yoksa `load()` açık "SDK başlıkları olmadan derlendi" nedeniyle düşer.
- `src/hardware/OecsSession.{hpp,cpp}`: kuran iş parçacığına bağlı RAII oturum. Sıra: thread/state/
  seçici/mutlak yol kontrolleri → load → enumerate → exact vendor+model+seri → süreç içi sahiplik →
  create → exclusive open. Her hata tamamlanan aşamaları ters sırayla geri alır. Tipli
  `OecsSessionError` (failure, stage, code); stage'ler `thread/state/select/load/enumerate/owner/
  create/open/close/destroy/unload`.
- `CMakeLists.txt`: yeni kaynaklar `visionflow_hardware`'a; isteğe bağlı `VISIONFLOW_OECS_INCLUDE_DIR`
  (yalnız Windows x64) ve `VISIONFLOW_OECS_RUNTIME_DLL`. Yeni CTest `industrial_backend_lifetime`;
  ikisi de verilirse opt-in `oecs_backend_local` (DLL dizini test PATH'inin başına eklenir).
- `tests/oecs_session_test.cpp`: çağrı kaydı tutan fake `OecsCApi` ile failure injection; `--sdk`
  modunda gerçek DLL smoke.
- Belgeler: sözleşme §5 notu, plan/kart durumu, progress, arşiv dizini, bu kayıt.

## Kararlar

- C API'de producer refcount yoktur; her oturum create/destroy çiftini kendisi eşler. SDK 3.5.2
  başlığında `MV_CC_Initialize/Finalize` yok; "init" katmanı load + sürüm + enumerate'tir.
- Close hatasında destroy yine yapılır. Destroy veya unload başarısızsa DLL kaldırılmaz
  (`libraryPinned`), sahiplik tutulur, oturum `Faulted` olur ve yeniden açılmaz; süreç yeniden başlatılır.
- Busy tanısı: `MV_E_BUSY`/`MV_E_ACCESS_DENIED` (başka uygulama olabilir) ve süreç içi ikinci sahip
  (create çağrılmadan). Sahiplik anahtarı exact vendor+model+seridir; seri tek başına seçmez, index
  fallback yoktur. Bu ilk sürüm process-local lease'tir.
- Yabancı iş parçacığından open/close reddedilir; yabancı iş parçacığında yıkım SDK çağırmaz,
  kaynakları bilerek sızdırır ve `qCritical` yazar. Worker/kuyruk sahipliği ICM-04e'dedir.
- `BackendCapabilities` tool backend kaydıdır (`require` reçete araçlarını kapılar); acquisition
  backend'i oraya eklenmedi. SDK'sız build'de ürün başlangıcında OECS yüklenmez.
- GenTLTransport, `producerMutex`, CameraService ve UI değişmedi. SDK başlığı/binary'si repoya kopyalanmadı.
