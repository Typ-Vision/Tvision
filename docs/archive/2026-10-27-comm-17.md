# COMM-17 — explicit TCP v3 servis entegrasyonu

Tarih: 27 Ekim 2026. Durum: yazılım kabulü tamamlandı.
Uygulayıcı: Codex

## Kapsam ve dosyalar

- `src/application/CommunicationTcpEndpoint.hpp/.cpp`: ayrı explicit Qt Network
  development listener. Konstruktor/Editor/Load socket açmaz; normal v2 endpoint'i
  değiştirmez. Aynı Runtime owner thread'inde async read/write, bounded 64 KiB
  read/framer ve 50 ms deadline tick; yeni bağlantıda yeni session, eski session
  reddi, açık port collision. Configured peer identity authentication değildir.
- INPUT profile ad/enum authority kontrolüyle immutable exact snapshot'a gider.
  Ortak router mevcut Running/software/guard/dependency/type/unit/frame/quality/
  local monotonic age kapılarını korur. Seçili bundle output group'u frozen
  profile ID, protocol/server role, actual listener address/port ile eşleşmelidir.
- `TriggerRouter.hpp/.cpp`: validation sonrası, coordinator.begin öncesi adapter
  hook'u REQUEST_INTENT ve ayrılmış UUID ile CYCLE_BEGIN yazar. Hook/begin hatası
  otomatik acquisition retry oluşturmaz. Communication origin exact input
  snapshot/revision ve request/sequence'ı Runtime terminal kaydına taşır.
- `ProductionRecipeService.hpp`, `ExecutionService.hpp/.cpp`, `RuntimeService.cpp`:
  optional reserved cycle identity worker ve exception yolunda korunur; default
  callers önceki kimlik üretimini kullanır. Trusted completion ticket/snapshot/
  digest ve existing Manual/v2 execution yolu korunur.
- `ProductionResultCodec.hpp/.cpp`, `ProductionRecipeService.cpp`,
  `MultiSourceRuntimeService.cpp`: v3 kaydı Result/Publish olmasa da boş,
  NOT_EVALUATED terminal10 bundle alır. Diğer callers'ın şeması değişmez.
- RESULT yalnız commit edilmiş terminal/bundle'dan hazırlanır, canonical
  payload/hash outbox'a bir kez yazılır. Terminal veya DELIVERY_PENDING commit
  başarısızsa RESULT yoktur. `retryRecording()` aynı completion/terminal/payload'ı
  kullanır; tekrar acquisition yoktur. Process içi duplicate/reconnect kayıtlı
  byte'ları okur; session zarfı değişse de payload/hash aynıdır.
- ACK exact request/resultId/hash ister; ACK_RECEIVED + ACK_COMMITTED olmadan
  ACKED/teslim bariyeri kalkmaz. Runtime Stop yeni admission'ı kapatır, cancellation
  sonuçtaki gerçek decision/field geçerliliğini bastırır; pending kayıt/delivery
  silinmez. Disconnect/buffered write Ready yapmaz.
- `src/app/plc_simulator.cpp`: `--v3`, INPUT JSON, sequence ve expected decision/
  field/JSON-value doğrulaması; exact ACK. V2 varsayılan ve alanları korunur.
  `tests/communication_tcp_test.cpp` ve CMake target/CTest kaydı gerçek localhost
  acceptance sağlar. Belgeler: plc-socket, wire, source-map, kart/plan ve devir.

## Sınırlar ve COMM-18 devri

Sonraki tek kart **COMM-18**: process restart/dedup/recovery. Bu kartın endpoint'i
normal UI'ya bağlanmaz; explicit development construction/listen API ve localhost
simulator kabulüdür. Process içi request table 128, input table 128; silent eviction
yoktur. Durable duplicate mevcut router kapısından edinimsiz reddedilir; process
restart için otomatik transport replay/reconciliation bu kartta uygulanmadı.
`DeliveryStore` REQUEST_INTENT/CYCLE_BEGIN kalıntısını RECOVERY_REQUIRED olarak
korur; hiçbir restart otomatik Run/cycle başlatmaz. V3 simulator `--resume`
kapalıdır. Otomatik ACK timeout/retry politikası **COMM-19**'dur; bu kart yalnız
explicit duplicate/reconnect ile persisted byte replay yapar. Runtime Stop
admission'ı kapatır; endpoint transport `stop()` listener'ı kapatır ve pending
kanıtı silmez. Pending transport restart/resume devri COMM-18'de ele alınmalıdır.
