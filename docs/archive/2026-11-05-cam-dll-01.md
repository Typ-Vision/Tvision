# CAM-DLL-01 — Ortak sistem DLL'sinde yanlış SDK çakışması

5 Kasım 2026 · Uygulayıcı: Codex.

Kullanıcı Opto Tek görüntü komutunda “Başka kurulumdan aynı adlı DLL yüklü;
uygulamayı yeniden başlatın: msvcr100.dll” hatasını bildirdi. Modül envanterinde
VisionFlow'un `C:/Windows/System32/MSVCR100.dll` dosyasını yüklediği görüldü.
Sistem kopyası 10.00.40219.325; OECS Runtime/Win64_x64 klasöründeki kopya
10.00.40219.455. Dosya hash'leri `build/icm/cam-dll-01/msvcr100-files.json`'da.
Bu kanıt kamera kablosu, profil veya UI düğme bağlantısı hatası değildir.

`RuntimeLibrary.cpp`, runtime/bağımlılık klasöründeki her DLL için aynı isimde
yüklü modülün mutlak yolunu karşılaştırıyordu. Windows'un merkezî ortak runtime
yüklemesi yanlışlıkla başka vendor kurulumu sayılıyordu. Şimdi zaten gerçek
Windows sistem dizininden yüklenmiş bağımlılıklar loader'a bırakılır. Açıkça
seçilen ana runtime bu istisnaya girmez; başka SDK dizininden yüklü vendor DLL
çakışmaları reddedilmeye devam eder. Windows DLL yükleme/export hataları korunur.

`tests/camera_service_test.cpp` mevcut runtime fixture'ına üç kontrol ekler:
sistemden yüklü kernel32'nin sibling kopyası yanlış çakışma üretmez; aynı dosyayı
ana runtime diye seçmek exact yol denetimini aşamaz; başka klasördeki vendor
dependency aynı isimle yüklüyse ret sürer. Test için sistem DLL'si değiştirilmez;
yalnız geçici build fixture'ına kopyalanır. Yeni bağımlılık veya sistem kurulumu yok.

Kanıt: `build/icm/cam-dll-01/`; runner/result/checkpoint, kaynak/test/config/binary
hash manifesti ve JUnit XML. Tam ON/OFF kullanıcı tercihiyle koşulmaz; ortak loader
için GenTL, OECS/pylon binding, Basler stream ve Camera Manager hedeflenir.
UI yerleşimi değişmez. Kullanıcının kamera/proje/INI verisi ve hand-eye/eye-to-hand
kaynakları değiştirilmez. Ürün production/G1/G3 izinleri açılmaz.

Release `build-tests`, `build-tests-final`, `build-final-on` exit 0.
`tests-on.xml`: **5/5**, 28.92 s — camera_transport, industrial_backend_binding,
pylon_backend_binding, basler_stream_trigger, ui_camera_manager. Ana EXE linki
kullanıcı normal çıkış yaptıktan sonra tamamlandı. Kullanıcı yeni EXE ile
aynı projede Ayarları oku → Tek görüntü operatör kontrolüne yönlendirildi.

Microsoft merkezî DLL deployment'ını sistem dizininde tanımlar:
[C++ deployment](https://learn.microsoft.com/en-us/cpp/windows/deployment-in-visual-cpp),
[CRT adları](https://devblogs.microsoft.com/cppblog/the-great-c-runtime-crt-refactoring/).
Bu kaynaklar exact OECS fiziksel kabulü veya patch sürümlerinin ayrıca kabulü değildir.

Pencereyi bilgisayar kullanımıyla okuma izni verilmedi; kullanıcı operatör testini
kendisi yapmayı seçti. Modül yolları salt okunur süreç tanısıyla incelendi.
Graph D:/TVision kökü/index, loader çağrı zinciri ve ilgili yolların coverage'i
kontrol edildi; graph'ın göstermediği OecsCApi/PylonSession kullanımı kaynakta
doğrulandı. Token/ücret sayaçları erişilemiyor. Push yok.
