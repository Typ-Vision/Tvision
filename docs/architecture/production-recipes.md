# Üretim doğrulaması, değişmez snapshot ve Runtime

7 Ekim 2026. A8 çekirdeği, 6C Measurement/Calibration resolver ve mevcut Runtime/Logs ekranlarına bağlandı. Üç applicationType aynı servis/engine yolundadır. Image File ve Webcam tek kare / host isteği desteklenir. Yürütme yapılandırmasının kabulü fiziksel kamera, lens, bağımsız referans uzunluğu veya üretim doğruluğu kabulü değildir.

## Taslak, doğrulama ve aktif sürüm

ProjectService Recipe taslağını düzenler/kaydeder; disk DRAFT/VALID/INVALID bir etkinleştirme izni değildir. ProductionRecipeService owner-thread üzerinde RecipeValidation üretir: UUID, principal, UTC, `execution_configuration` kapsamı, içerik ve bağımlılık SHA-256 kimlikleri. ProductionSnapshot const shared pointer ile recipe kopyası, proje klasörü, validation ve dependency manifesti taşır. Worker yalnız bu snapshot'ı yakalar. Taslak toleransı, isim veya normal Save aktif snapshot'ı değiştirmez; kurulum/kaynak beyanı değişimi sonraki çevrimi engeller.

İçerik kimliği recipe ID/revizyon/şema, isim/açıklama, applicationType, kamera/kalibrasyon referansı, kesin binding, tüm definition ve mutlak proje klasörünü kapsar. Aynı recipeVersion altında farklı taslaklar farklı config/validation ID taşır. Status ve tarihler izin değildir. Manifest engine version 3, kullanılan tool ID/kind/registry version, Match model/geometri, resolver asset kimlikleri ve kalibrasyon dependency içerir. Hash bütünlüktür; binary imzası veya kullanıcı kimliği kanıtı değildir.

Validate typed DAG, required inputs, enabled upstream, tek source, parametreler, Match model decoder/doku/ROI ve tracking anchor kontrolünü yapar. Yedi built-in tool desteklenir; compiled extension üretim kabulü yoktur. Enabled Measurement kesin calibrationBinding ister. RuntimeService.probe worker'da yeni source acquisition yapar; preview veya editor sonucu validation karesi değildir. CalibrationWorkflow ayrı planarSetup lens/düzlem beyanı ve edinilmiş gerçek source/çözünürlük/koordinattan current installation oluşturur; CalibrationService evidence replay ve latest/binding eşleşmesini kontrol eder. Her Runtime cycle ediniminden sonra aynı resolver yeni gerçek frame'i yeniden denetler. Çözünürlük değişmişse Measurement ERROR/boş çıktı olur.

## Yetki ve komutlar

`Authorize(principal, action)` trusted application policy'sidir; Validate/Activate/Rollback/Run ayrı servis eylemleridir. Policy veya principal yoksa varsayılan ret vardır. UI rol boolean'ı veya disk validation UUID'si yetki sağlamaz. RuntimeIdentity.localEngineer Windows GetUserNameW ile OS oturumunun kimliğini alır; environment username kullanılmaz. İlk masaüstü politika aynı yerel oturuma dört Runtime eylemi verir ve ekranda Yerel Engineer olarak gösterir. Users/Administrator yönetimi, parola oturumu, kalıcı rol dağıtımı ve Operator ayrımı uygulanmadı; Users ekranı hazırlıktır. Yerel dosyalara erişimi olan kullanıcıya karşı arşiv imzalama/korumalı audit henüz yoktur.

Runtime: Taslağı doğrula → Etkinleştir → Tek çevrim. Activate current draft content/path ve dependency'yi yeniden kontrol eder. Eski validation reddedilir. Rollback yalnız bu servis oturumunda önceden etkinleşmiş sürümleri kullanır ve güncel dependency'yi yeniden kontrol eder. Snapshot/event commit başarısızsa önceki aktif sürüm korunur. Snapshot geçmişi oturum başına 16 (çekirdekte ayarlanabilir 1–256); limit dolunca otomatik silme yoktur.

beginCycle Run yetkisi, latest dependency ve tek in-flight lease kontrolünden sonra disk CYCLE_BEGIN event'ini commit eder; kayıt başarısızsa acquisition başlamaz. Busy sırasında Run/Activate/Rollback reddedilir. RuntimeService.validate da yeni installation'ın live cycle'ı değiştirmesini engeller. JobSession future/cancel/close sahipliğini taşır; worker bitmeden veya terminal kayıt beklerken pencere kapanmaz. Stop cooperative'dir, driver/algoritma hard interruption değildir. Editor ve Camera Manager acquisition komutları Runtime işi/kaydı sürerken engellenir.

finishCycle ticket, recipe/config, terminal state, duplicate cycle/tool, frame/output lineage ve süreyi denetler. Measurement kararı DONE, gerçek mm/pass çıktısı, kesin calibration manifesti ve aktif ham toleransla eşleşmelidir. FAIL yürütme hatası değildir; DONE/FAIL kalır. İptal tüm output/overlay/kararları bastırır. UI ancak terminal kayıt commit edildikten sonra sonucu yayımlar. Disk/lock hatası lease'i ve aynı pending record'u korur, yeni çevrimi engeller; Kaydı tekrar yaz aynı kaydı atomik/idempotent tamamlar, acquisition veya PLC retry değildir.

## Kalıcı arşiv ve Logs

`<proje.vfproject>.production/{snapshots,events,cycles}/<UUID>.json`. Snapshot schema 1 tam recipe/proje kopyası, content/dependency, principal/scope/zaman taşır. Event schema 1 activation/rollback/CYCLE_BEGIN içerir. Cycle schema 2 beginEventId, ticket/principal, recipe/version/validation/config/dependency, engine/tool/model/calibration, UTC başlangıç/bitiş, cycle/frame/source/coordinate, tool state/errorCode, gerçek sayısal/boolean/point/region output ve tool bazında decision/calibration içerir. Image tamponları ve robot pose üretilmez/kaydedilmez. Global recipe AND/OR kararı yoktur; Measurement kararları ayrı listelenir. `communicationState=NOT_REQUESTED`, PLC teslimi yapılmaz.

ProductionStore format/schema/kind/UUID/payload SHA-256 wrapper'ı doğrular. Append-only: mevcut UUID farklı içerikle üzerine yazılmaz; aynı kayıt tekrar yazımı idempotent. QLockFile (otomatik stale break yok) ve direct fallback kapalı QSaveFile her kayıt için kullanılır. Sınırlar: dosya 20 MiB, toplam 512 MiB/10000 kayıt; recent read 1–256 kayıt/64 MiB. Limitte yeni commit reddedilir; otomatik retention yoktur. Logs mevcut projenin son 128 terminal kaydını salt okunur gösterir; detay JSON bütün kimlik/birimleri korur.

Restart terminal kayıtları/kanıtları okunabilir; validation/active/rollback izni arşivden geri yüklenmez. Yeniden fresh acquisition → Validate → Activate gerekir. Process crash terminal commit öncesinde olursa CYCLE_BEGIN event'i bulunabilir, tamamlanmış sonucu veya PASS'i kanıtlamaz; bu event'ler arşiv dosyalarında saklanır, Logs tamamlanmış cycle'ları listeler. Henüz crash reconciliation UI yoktur. Arşiv/project/catalog ayrı commit'lerdir, birlikte transaction veya taşınabilir container değildir. Disk full/power loss/uzak disk, OS durability, cross-process production lease ve çok kullanıcı rol kabulü açık; IO atomik ve boyut sınırlı olsa da owner-thread archive commit'i yavaş disk üzerinde UI geciktirebilir.
